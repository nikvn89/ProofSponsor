# ProofSponsor — Reviewer Testing Guide

This guide provides a complete end-to-end test of ProofSponsor on GenLayer Studionet.

Almost all test data is provided for copy/paste.

The only wallet-specific value the reviewer must insert manually is the ownership marker generated by ProofSponsor.

## Live dApp

https://proofsponsor-gl.vercel.app/

## Contract

**GenLayer Studionet**

```text
0x3Aa42FdD6EC0299c4172aaB47C4f0586625736bC
```

---

# Test 1 — APPROVED

This test should result in:

```text
APPROVED
```

## Step 1 — Connect Wallet

Open the live dApp and connect a wallet for GenLayer Studionet.

---

## Step 2 — Create Sponsorship

Open **Sponsorship Desk**.

### Sponsorship ID

Use a unique ID.

Copy:

```text
review-approved-01
```

If it already exists, change the number:

```text
review-approved-02
```

### Title

Copy:

```text
GenLayer Intelligent Contract Review Test
```

### Sponsor brief

Copy:

```text
Creator must publish a meaningful public article explaining how GenLayer Intelligent Contracts use decentralized AI validator consensus. The article must contain the required SponsorJudge ownership proof marker and provide meaningful educational information about GenLayer.
```

Click:

```text
Publish sponsorship
```

Wait until the campaign displays:

```text
ACTIVE
```

---

## Step 3 — Generate Ownership Proof

Open **Creator Workspace**.

Use the connected wallet as the creator wallet.

Click:

```text
Generate ownership proof
```

ProofSponsor will generate:

```text
SPONSORJUDGE_PROOF:<your-wallet>
```

Copy the exact marker.

Example only:

```text
SPONSORJUDGE_PROOF:0x1234567890...
```

Do not use the example marker. Use the marker generated for your own wallet.

---

## Step 4 — Create Public Evidence

Open:

https://pastebin.com/

Create a new public or unlisted Pastebin.

Copy the entire article below:

```text
GenLayer Intelligent Contracts and Decentralized AI Consensus

GenLayer Intelligent Contracts extend blockchain applications beyond purely deterministic execution.

Traditional smart contracts are effective when rules can be expressed using exact values and deterministic conditions. However, many real-world decisions require evaluating meaning, context, and qualitative information.

GenLayer enables Intelligent Contracts to use decentralized AI validator consensus for these non-deterministic decisions. Multiple validators can evaluate public information and reach consensus about whether a requirement has been meaningfully satisfied.

For sponsorship workflows, this allows a sponsor to define qualitative requirements while creators provide public evidence of their completed work. GenLayer validators can inspect that evidence and determine whether the creator actually fulfilled the sponsorship brief.

ProofSponsor uses this capability to turn sponsorship fulfillment into a verifiable onchain result.

Creator ownership proof:

PASTE_YOUR_SPONSORJUDGE_PROOF_HERE
```

Replace:

```text
PASTE_YOUR_SPONSORJUDGE_PROOF_HERE
```

with the exact marker generated in Step 3.

For example:

```text
Creator ownership proof:

SPONSORJUDGE_PROOF:0x1234567890...
```

Publish the Pastebin.

Copy the resulting URL.

Example:

```text
https://pastebin.com/XXXXXXXX
```

---

## Step 5 — Submit Deliverable

Return to **Creator Workspace**.

### Delivery note

Copy:

```text
I completed the sponsored article explaining GenLayer Intelligent Contracts and decentralized AI validator consensus. The public article also contains the required SponsorJudge ownership proof marker.
```

### Public deliverable URL

Paste the URL created in Step 4.

Example:

```text
https://pastebin.com/XXXXXXXX
```

Click:

```text
Submit deliverable
```

Confirm the transaction once and wait for it to be accepted.

Do not repeatedly click the button while the transaction is processing.

---

## Step 6 — Load Delivery

Open **Verification Center**.

Use the same creator wallet.

Click:

```text
Load delivery
```

Expected submission state:

```text
SUBMITTED
```

The dApp should display the submitted evidence URL and delivery note.

---

## Step 7 — Run GenLayer Adjudication

Click:

```text
Verify delivery with GenLayer
```

Confirm the transaction once.

GenLayer validators now evaluate:

```text
Sponsor brief
      +
Public evidence
      +
Creator ownership proof
      ↓
Decentralized AI adjudication
```

AI adjudication is asynchronous and may take some time.

Do not repeatedly click the verification button.

---

## Step 8 — Expected APPROVED Result

The provided article meaningfully satisfies the sponsorship brief and contains the correct ownership marker.

Expected result:

```text
APPROVED
```

The dApp should display:

```text
100%

Delivery verified

APPROVED
```

The APPROVED test is complete.

# Test 2 — REJECTED

This optional test demonstrates that ProofSponsor does not automatically approve submitted evidence.

## Step 1 — Create Another Sponsorship

Use a new unique ID:

```text
review-rejected-01
```

Title:

```text
GenLayer Intelligent Contract Rejection Test
```

Use the same Sponsor brief:

```text
Creator must publish a meaningful public article explaining how GenLayer Intelligent Contracts use decentralized AI validator consensus. The article must contain the required SponsorJudge ownership proof marker and provide meaningful educational information about GenLayer.
```

Publish the sponsorship.

---

## Step 2 — Generate Ownership Proof

Generate the ownership proof for the creator wallet normally.

Copy the exact:

```text
SPONSORJUDGE_PROOF:<your-wallet>
```

---

## Step 3 — Create Intentionally Invalid Evidence

Create another Pastebin.

Copy:

```text
This is an unrelated test page.

This content does not explain GenLayer Intelligent Contracts and does not meaningfully discuss decentralized AI validator consensus.

It intentionally fails the sponsorship requirements so that the negative adjudication path can be tested.

Creator ownership proof:

PASTE_YOUR_SPONSORJUDGE_PROOF_HERE
```

Replace the placeholder with the exact ownership marker generated by ProofSponsor.

Publish the Pastebin and copy its public HTTPS URL.

---

## Step 4 — Submit

Delivery note:

```text
Submitting this public deliverable for sponsorship verification.
```

Paste the new Pastebin URL into:

```text
Public deliverable URL
```

Click:

```text
Submit deliverable
```

Wait for acceptance.

---

## Step 5 — Verify

Open **Verification Center**.

Load the delivery and click:

```text
Verify delivery with GenLayer
```

Wait for GenLayer adjudication.

Expected result:

```text
REJECTED
```

This demonstrates that ProofSponsor evaluates semantic fulfillment instead of simply approving any submitted URL.

---

# What These Tests Demonstrate

The two tests exercise the same deployed Intelligent Contract but provide different evidence quality.

```text
Valid evidence
+ correct ownership marker
        ↓
APPROVED


Invalid evidence
+ correct ownership marker
        ↓
REJECTED
```

This demonstrates the core GenLayer use case of ProofSponsor: decentralized adjudication of qualitative sponsorship fulfillment.
